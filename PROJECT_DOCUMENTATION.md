# FCADBot: полная документация проекта

Документ описывает фактическое состояние проекта FCADBot, его назначение, архитектуру, функциональность, данные, API, безопасность, запуск, деплой и историю изменений.

## 1. Общие сведения

**Название:** FCADBot / СС ФКП БГУИР
**Тип:** Telegram Mini App и веб-приложение для Студенческого совета факультета компьютерного проектирования БГУИР
**Первый коммит:** 3 мая 2026 года
**Основной домен production:** `fcadbot.site`
**Репозиторий:** `fcadbott`
**Основная задача:** цифровизация работы студенческого совета: освобождения от занятий, премирование, мероприятия, посещаемость, баллы, ходатайства, сектора и уведомления через Telegram.

Проект начинался как система для освобождений и премирования, затем был расширен до единой операционной платформы студсовета.

## 2. Что делает продукт

FCADBot объединяет следующие процессы:

- авторизация координаторов через Telegram Mini App;
- регистрация и вход студентов по ФИО, номеру студенческого и Telegram username;
- управление студентами и координаторами;
- распределение студентов по секторам студсовета;
- создание и обработка освобождений от занятий;
- подготовка докладных и документов Word;
- подача и согласование премий;
- публикация мероприятий;
- регистрация студентов на мероприятия;
- назначение организаторов и сканеров;
- QR-регистрация входа и выхода;
- ручная отметка посещаемости;
- автоматическое начисление баллов;
- отправка списков участников и уведомлений в Telegram;
- подача и рассмотрение ходатайств;
- статистика, рейтинги и журнал активности;
- публичный лендинг факультета для обычного браузера.

## 5. Архитектура

### 5.1 Frontend

Frontend написан на React и TypeScript, собирается Vite.

Точка входа: `frontend/src/main.tsx`. Корневой компонент: `frontend/src/App.tsx`.

Отдельного React Router нет. Переключение разделов выполняется состоянием вкладки в `App.tsx` и нижним меню `NavBar`.

Клиент API находится в `frontend/src/utils/api.ts`. Все запросы используют относительный путь `/api`, поэтому frontend и backend могут работать под одним доменом.

### 5.2 Backend

Backend работает на Express и TypeScript.

Точка входа: `backend/src/index.ts`.

Backend:

- загружает `.env` через `dotenv`;
- поднимает CORS;
- принимает JSON через Express;
- обслуживает статические frontend-файлы;
- подключает middleware авторизации;
- регистрирует API-маршруты;
- запускает Telegram-бота;
- запускает фоновые напоминания о мероприятиях.

### 5.3 База данных

Используются PostgreSQL и Prisma ORM.

Prisma Client создаётся в `backend/src/lib/prisma.ts`. Основная схема находится в `backend/prisma/schema.prisma`, изменения структуры фиксируются в `backend/prisma/migrations`.

### DEPUTY

Заместитель председателя имеет расширенные административные права и доступ к основным операциям руководства.

### DEAN

Представитель деканата имеет административный доступ к подтверждениям, документам, ходатайствам и статистике.

### SECRETARY

Секретарь участвует в административной работе, документах, освобождениях и премиях. Конкретные проверки прав задаются в отдельных backend-маршрутах.

### COORDINATOR

Координатор работает преимущественно со своим сектором:

- видит студентов своего сектора;
- может добавлять существующего студента в свой сектор;
- может удалять студента из своего сектора;

- создаёт освобождения;
- подаёт премии;
- создаёт и сопровождает мероприятия;
- обрабатывает заявки в рамках доступных прав;
- может быть назначен сканером или организатором.

Правило управления секторами: обычный координатор может менять только сектор, записанный в его профиле. Административные роли могут управлять всеми секторами.

## 8. Авторизация

### 8.1 Координатор через Telegram

Telegram Mini App предоставляет `window.Telegram.WebApp.initData`.

Frontend отправляет его на:

```text
POST /api/auth/verify
```

Backend:

1. извлекает `hash` и параметры `initData`;
2. сортирует параметры;
3. вычисляет HMAC-SHA256 через `BOT_TOKEN`;
4. сравнивает вычисленный hash с Telegram hash;
5. извлекает Telegram username;
6. ищет координатора по username;
7. сохраняет `chatId` и фото профиля;
8. выдаёт подписанную сессию.

### 8.2 Сессия

Сессия хранится в cookie `fkp_session`.

Свойства:

- срок действия 7 дней;
- `HttpOnly`;
- `Secure`;
- `SameSite=Lax`;
- подпись HMAC-SHA256;
- секрет — `SESSION_SECRET`.

`SESSION_SECRET` обязателен. Использование `BOT_TOKEN` как запасного секрета запрещено.

### 8.3 Студент

Регистрация:

```text
POST /api/auth/student-register
```

Поля:

- `fullName`;
- `studentCardNumber`;
- `telegramUsername`;
- `groupNumber`;
- `budgetStatus`;
- необязательный Telegram `initData`.

При регистрации студент сопоставляется с предварительно загруженной записью в базе. После успешного сопоставления сохраняются username, chat ID и фото.

Вход:

```text
POST /api/auth/student-login
```

Frontend также сохраняет студента в `localStorage` под ключом `student`.

### 8.4 Тестовый режим

В development поддерживается URL вида:

```text
http://localhost:5173?user=wolllip
```

В production параметр тестового пользователя отключён для production-домена. Разрешение тестовой авторизации в production возможно только при явном `ALLOW_TEST_AUTH=true`.

## 9. Защита API

Middleware находится в `backend/src/middleware/auth.ts`.

Публичными являются:

- `GET /api/events`;
- все `/api/auth/*`;
- `/api/bot-webhook`.

Остальные запросы требуют валидную сессию.

Middleware дополнительно сравнивает идентификаторы из запроса с идентификатором сессии:

- `coordinatorId`;
- `creatorId`;
- `authorId`;
- `userId`;
- query `coordinatorId`.

Это предотвращает подмену пользователя через тело запроса.

Для студенческой сессии административное значение `role` удаляется из тела или query-параметров.

На auth-маршруты и сканирование установлены простые in-memory rate limits.

## 11. Telegram-бот

Основная реализация: `backend/src/services/bot.ts`.

Бот используется для:

- команды `/start`;
- сохранения `chatId`;
- кнопки открытия Mini App;
- уведомлений об освобождениях;
- уведомлений о премиях;
- уведомлений о ходатайствах;
- уведомлений о мероприятиях;
- сообщений назначенным сканерам и организаторам;
- уведомлений о посещении;
- уведомлений о баллах;
- отправки документов;
- отправки списка участников.

Режим работы:

- polling, если webhook URL не задан;
- webhook, если настроен `WEBHOOK_URL`.

Webhook endpoint:

```text
POST /api/bot-webhook
```

При заданном `TELEGRAM_WEBHOOK_SECRET` проверяется заголовок `X-Telegram-Bot-Api-Secret-Token`.

Списки участников отправляются обычным текстом частями, чтобы не ломать Markdown-разметку на именах и не превышать лимит Telegram-сообщения.

Документы Word создаются пакетами `docx`.

- `backend/src/services/petitionDocGenerator.ts` — ходатайства.

Документы содержат официальные данные, списки студентов, группы, номера студенческих, причины, суммы и подписи/служебные поля согласно конкретному процессу.

## 13. Модель данных

### Coordinator

Координатор:

- `id`;
- `fullName`;
- `telegramUsername`;
- `role`;
- `sector`;
- `chatId`;
- `photoUrl`.

### Sector

Сектор:

- `id`;
- уникальное `name`;
- уникальный `coordinatorId`;
- список `members`.

### SectorMember

Историческая/отдельная модель участника сектора:

- `sectorId`;
- `fullName`;
- `groupNumber`;
- `studentCardNumber`.

Уникальность: `sectorId + fullName + groupNumber`.

### Student

Студент:

- `id`;
- `fullName`;
- `birthDate`;
- `groupNumber`;
- `studentCardNumber`;
- уникальный nullable `telegramUsername`;
- `chatId`;
- массив `sectors`;
- `budgetStatus`;
- `photoUrl`.

### Exemption и ExemptionStudent

`Exemption` хранит дату, причину, автора, статус, отметки выставления и печати.

`ExemptionStudent` связывает освобождение со студентом или внешним человеком без записи в Student.

### Event

Мероприятие содержит:

- название;
- дату и место;
- описание;
- автора;
- регистрационный дедлайн;
- баллы за посещение;
- баллы за организацию;
- лимит участников;
- статус;
- аудиторию;
- разрешённые группы;
- признак faculty-only;
- необходимость подтверждения;
- назначения сканеров и организаторов.

### EventApplication

Заявка студента:

- студент;
- мероприятие;
- тип участия: `VISITOR`, `PARTICIPANT`, `ORGANIZER`;
- статус;
- комментарии;
- QR token;
- время входа и выхода;
- отметки checked-in/checked-out;
- связанные Attendance.

### Attendance

Отметка содержит:

- заявку;
- тип `CHECK_IN` или `CHECK_OUT`;
- сканировщика;
- время сканирования.

### PointTransaction

Операция баллов содержит:

- студента;
- количество баллов;
- тип `ATTENDANCE`, `ORGANIZATION` или `MANUAL_ADJUSTMENT`;
- необязательное мероприятие;
- причину;
- автора;
- статус `ACTIVE` или `CANCELLED`.

### BonusSubmission и BonusEntry

Заявка премирования связана с координатором, месяцем, годом и статусом. Внутри находятся строки с суммой, студентом/внешним получателем, причиной и бюджетными полями.

### Petition

Ходатайство содержит студента, тип, статус, баланс при подаче, итоговые баллы, комментарий и проверяющего. Снимки баллов сохраняются в `PetitionPointSnapshot`.

## 14. API

Общий префикс: `/api`.

### Auth: `/api/auth`

- `POST /verify` — проверка Telegram Mini App и вход координатора;
- `POST /student-register` — регистрация студента;
- `POST /student-login` — вход студента;
- `PUT /profile` — обновление аватара;
- `GET /avatar/:chatId` — прокси Telegram-фотографии.

## 15. Статусы и бизнес-правила

### Освобождения

- координатор создаёт освобождение;
- руководящая роль может получить автоматический approved-статус;
- обычная заявка может быть pending;
- после выставления обычному координатору редактирование ограничивается;
- при выставлении студентам могут отправляться Telegram-уведомления.

### Премии

- подача открыта с 20-го числа до последнего дня месяца;
- одна заявка на месяц и координатора;
- координатор может редактировать pending-заявку;
- руководство изменяет строки, подтверждает или откладывает их;
- подтверждённые данные используются для Word-документа.

### Ходатайства

- студент должен иметь минимум 100 активных баллов;
- за подачу списывается 100 баллов;
- студент на бюджете не может подать ходатайство на скидку;
- один тип ходатайства нельзя подать повторно;
- решение принимают председатель, декан или заместитель.

### Мероприятия

- мероприятие может быть черновиком или опубликованным;
- заявка может быть pending, approved, rejected, cancelled или завершённой по посещению;
- QR доступен только для approved-заявки;
- вход должен быть отмечен до выхода;
- при выходе обновляется посещение и начисляются баллы;
- организатор получает отдельное количество баллов.

## 16. Telegram-уведомления

Уведомления предусмотрены для:

- новых мероприятий;
- заявок на мероприятие;
- решений по заявкам;
- назначений сканировщиком;
- назначений организатором;
- входа и выхода;
- начисления баллов;
- достижения 100 баллов;
- создания, подтверждения и отклонения освобождения;
- подачи, подтверждения и отклонения ходатайства;
- подачи и подтверждения премии.

Для отправки уведомлений пользователю нужен сохранённый Telegram `chatId`. Обычно он сохраняется после команды `/start` или успешной авторизации из Telegram.

## 20. Production-деплой

Рекомендуемая схема:

```text
Telegram / Browser
        │
        ▼
   Cloudflare / HTTPS
        │
        ▼
      Nginx
      ├── static frontend
      └── /api → Express :3001
                       │
                       ▼
                   PostgreSQL
```

В production использовались:

- Nginx;
- systemd unit `fkp-backend.service`;
- PostgreSQL;
- домен `fcadbot.site`;
- Cloudflare;
- Telegram webhook или polling.

Production-пути текущих скриптов ориентированы на:

```text
/root/fcadbott/fkp-ss-app
/root/fcadbott/fkp-ss-app/backend
/root/fcadbott/fkp-ss-app/frontend/dist
```

`start-backend.sh` запускает backend в предположении, что PostgreSQL-контейнер и проект находятся по этим путям. `heal-db.sh` проверяет БД, применяет миграции и запускает seed при пустой базе.

При переносе на новый сервер нужно сохранить:

- базу PostgreSQL;
- `.env` и секреты;
- `frontend/public` и ассеты;
- systemd unit;
- Nginx-конфигурацию;
- SSL/Cloudflare настройки;
- Telegram webhook;
- резервную копию до переключения DNS.


Студенты не видны:

```bash

```

Бот не отвечает:

- проверить webhook/polling;
- проверить, что пользователь писал `/start`.

Blank screen:

- проверить browser console;
- проверить загрузку JS и CSS;
- проверить актуальность `index.html` и asset hashes;
- очистить Cloudflare cache только после проверки origin.

## 22. Безопасность и известные ограничения

- `.env` не должен попадать в Git;
- Telegram bot token необходимо хранить только на сервере;
- `SESSION_SECRET` должен быть длинным случайным секретом;
- production test mode должен оставаться выключенным;
- PII нельзя отдавать обычным координаторам без необходимости;
- in-memory rate limit сбрасывается при перезапуске процесса;
- некоторые старые маршруты принимают `role` из тела запроса, поэтому авторизация должна дополнительно контролироваться middleware;
- часть старых API-методов возвращает общий `Server error`, что усложняет диагностику;
- production fallback frontend в `backend/src/index.ts` содержит жёсткий абсолютный путь;
- `README.md` не полностью отражает фактическое количество страниц и API;
- часть production-исправлений может находиться в рабочем дереве или на сервере, но не в истории Git.

## 26. Краткое резюме

FCADBot — это полноценная внутренняя платформа студенческого совета ФКП БГУИР. Она выросла из автоматизации освобождений и премий в систему управления студентами, секторами, мероприятиями, заявками, посещаемостью, баллами, ходатайствами, документами и Telegram-коммуникациями.

Основной стек: React + TypeScript + Vite на frontend, Node.js + Express + Prisma + PostgreSQL на backend, Telegram Bot API для коммуникаций и Nginx/Cloudflare для production-доступа.
